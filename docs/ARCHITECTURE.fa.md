# معماری روشنا ۲

## مرزهای محصول

روشنا دو نوع داده را عمداً از هم جدا می‌کند:

- فضای شخصی: برنامه‌ها، هدف‌ها، عادت‌ها، ژورنال، چرخ زندگی، تمرکز و تاریخچه گجت‌ها در IndexedDB مرورگر می‌مانند و با فایل JSON پشتیبان گرفته می‌شوند.
- فضای آنلاین: حساب کامیونیتی، پروفایل عمومی، رابطه‌ها، پیام‌ها، گزارش‌ها، اعلان‌های حساب و بازی‌های آنلاین در `data/platform.sqlite` روی سرور ذخیره می‌شوند.

پنل مدیریت به نوشته‌ها و برنامه‌های شخصی دسترسی ندارد. بک‌اند آنلاین از SQLite با WAL و یک پردازش PM2 استفاده می‌کند. برای چند پردازش یا چند سرور، مهاجرت به PostgreSQL، ذخیره‌سازی شیء و Redis لازم است.

## Design System و معماری رابط

`app/globals.css` پایه قدیمی و سازگاری بخش‌های موجود را نگه می‌دارد. `app/polish.css` تم روشن/تاریک و ۱۲ رنگ اصلی را تعریف می‌کند. `app/superapp.css` توکن‌ها، پوسته سوپراپ، جستجوی سراسری، اعلان‌ها، onboarding، skeleton و رفتار responsive را در بر دارد. CSS هر ماژول فقط کلاس‌های همان ماژول را تعریف می‌کند.

سه بخش سنگین با `next/dynamic` جدا می‌شوند و فقط هنگام بازشدن دانلود می‌شوند. خطای هر ماژول با Error Boundary محلی مهار می‌شود تا ابزارهای شخصی همچنان کار کنند. `prefers-reduced-motion` و انتخاب «حرکت کمتر» همه انیمیشن‌های غیرضروری را خاموش می‌کند.

## مدل داده آنلاین

هسته مشترک در `lib/server/platform.ts` است. جدول‌های اصلی:

- `members`, `member_sessions`, `member_follows`, `member_friends`, `member_blocks`
- `community_rooms`, `community_memberships`, `community_messages`, `community_attachments`, `community_reactions`, `community_reports`, `community_audit`
- `platform_notifications`
- جدول‌های بازی آنلاین و دفتر ثبت XP در ماژول بازی
- `usage_daily` برای شمارش جمعی و اختیاری بازدید بخش‌ها با نگهداری ۹۰ روزه

کلید خارجی، تراکنش و محدودیت ورودی در لایه سرور اعمال می‌شود. نتیجه بازی رتبه‌ای فقط از موتور معتبر سمت سرور وارد leaderboard می‌شود؛ امتیاز بازی‌های آفلاین محلی و غیرقابل‌تأیید است.

## سطح API

- `/api/community/*`: نشست، پروفایل، کشف کاربران، رابطه‌ها، اتاق‌ها، پیام، واکنش، فایل، گزارش، بلاک و اعلان‌ها.
- `/api/games/*`: matchmaking، lobby خصوصی/عمومی، state معتبر بازی، حرکت، تماشا، سابقه و leaderboard.
- `/api/market/*`: proxy محدود به آداپتورهای ثابت، cache و stale fallback؛ هیچ URL دلخواهی از کاربر دریافت نمی‌شود.
- `/api/analytics`: شمارش اختیاری و بدون شناسه؛ خواندن فقط برای مدیر.
- `/api/admin`: تنظیمات محتوا و نشست مدیر موجود.

قرارداد دقیق هر زیرسیستم در فایل‌های `docs/COMMUNITY.fa.md`، `docs/GAMES.fa.md` و `docs/MARKET-SOURCES.fa.md` ثبت می‌شود.

## امنیت و حریم خصوصی

رمزها با scrypt و salt تصادفی مشتق می‌شوند؛ session token خام فقط در cookie امن HttpOnly/SameSite قرار می‌گیرد و hash آن در دیتابیس ذخیره می‌شود. درخواست‌های mutation با Origin، HTTPS در production، محدودیت اندازه، schema validation و rate limit کنترل می‌شوند. بلاک دوطرفه باید هم در خواندن و هم نوشتن اعمال شود. فایل‌ها فقط پس از احراز هویت و بررسی عضویت اتاق تحویل می‌شوند؛ HTML، SVG و فایل اجرایی پذیرفته نمی‌شود.

Nginx نباید پوشه `data`، `.env.local`، `.next`، اسکریپت‌ها یا مخزن Git را به‌صورت فایل ایستا منتشر کند. پشتیبان رمزگذاری‌شده دیتابیس و سیاست حذف حساب قبل از عرضه عمومی لازم است.

## مدل درآمد سالم

نسخه فعلی پرداخت واقعی یا موجودی ساختگی نشان نمی‌دهد. معماری تجاری پیشنهادی:

1. Premium برای سقف بیشتر گروه، پوسته پروفایل، تاریخچه بیشتر و امکانات سازمان‌دهی؛ بدون قفل‌کردن ایمنی یا بلاک/گزارش.
2. Badge صرفاً تزئینی و شفاف؛ Badge تأیید هویت جدا و فقط پس از فرایند واقعی.
3. Credit و Gift فقط با ledger دوطرفه، idempotency key، رسید پرداخت و امکان بازپرداخت؛ هرگز عدد موجودی را در کلاینت معتبر فرض نکنید.
4. تبلیغات محدود، برچسب‌دار و قابل خاموش‌کردن با Premium؛ بدون استفاده از ژورنال، گفتگو یا داده سلامت برای هدف‌گیری.
5. امکانات کامیونیتی سازمانی و تورنمنت اسپانسری پس از تکمیل ضدتقلب و ابزار مدیریت.

برای پرداخت، یک Provider قانونی متناسب با بازار هدف، webhook امضاشده، جدول entitlement و ledger مالی جدا لازم است. فعال‌کردن UI فروش پیش از این زیرساخت مجاز نیست.

## مسیر مقیاس‌پذیری

مرحله بعدی فنی: PostgreSQL و migration tool، Redis برای rate limit/presence، WebSocket gateway برای chat و بازی، object storage با malware scan، job queue، push notification با subscription صریح، حذف/خروجی حساب، observability و backup/restore آزمایش‌شده. سپس پرداخت و entitlement، ضدتقلب، tournament و moderation پیشرفته اضافه شوند.
